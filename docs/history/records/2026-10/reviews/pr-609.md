## Findings

1. **should-fix (robustness, fail-open).** `implInstance` returns null silently on several "cannot
   happen" paths (`own.items.len != call.args.len`, `outer.params.len != outer.args.len`,
   `typeMethod` null, `ctx.types.get(ty) != .function`). It also works out a method's own parameters a
   second time (`typeParamOf` or an int `ct_syms` slot) where `instantiateCall` already did
   (`typeParamOf orelse intSlot`). If the two ever disagree (a new kind of compile-time parameter, say),
   the check is skipped without a word and the hole this PR closes is open again. No probe reached
   these paths. Suggest a self-check assertion (`build_options.self_check`) on the count mismatches, or
   recording the own parameters once at the call.
2. **nit (cost).** `recordApiCall` never deduplicates, and `expand` runs `implInstance` for every entry
   at every instance: `witnessFor`, `formatType`, a print and two concats, before the
   `fn_instance_set` check throws the result away. In a synthetic file (40 types × 400 identical calls)
   typecheck took 8.8-11.5 ms, against 1.8 ms when the same instances make no API calls. Trig's check
   time is not measured. Deduplicate `(recv, api, method, args)` when recording, or look in the set
   before building the name.
3. **nit (messages).** An addition's instance shows the addition's parameters as its own:
   `Map.look[Int, Int, Float] cannot use K = Float` (v1). The ever-deeper message shows a generic
   parameter in a concrete trail: "through `probe[Sq, Wrap[K]]`" (p7; the `fn_uses` path already did
   this). And `checkSelfNesting` skips API calls (`reached != null`), so a public generic that nests
   itself through an API is reported at the instance in the using module (m4), not where it is declared
   as INTERNALS says. That is still sound.
4. **nit (doc).** The INTERNALS paragraph is one long run-on block. It could say plainly that a
   through_api instance's own bounds and misplaced arguments are reported by the API method's
   instance, and that this is sound only because conformance makes the parameters and bounds the same.
