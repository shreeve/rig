## Findings

### 1. should-fix: API default methods are generic bodies whose instances are never checked
`Self` in a default method is a bounded type variable without `Syncs`, so the task is local (emit: `spawnLocal`). The `.task` requirement on `Self` is recorded but never checked against a conformer, so a conformer holding an owned closure or an API object reaches a local task. The same value given directly is rejected.

n5c.rig:
```rig
api Runs
  fun id(?@) -> Int
  fun go(?@) -> Int
    t = look(?@)&
    >t
fun look[T](x: ?T) -> Int
  1
obj Holder: Runs
  s: ^{Shape}          # or f: *fun() -> Int  (n5.rig: accepted, runs)
  fun id(?@) -> Int
    1
...
  print(h.go())        # accepted
  t = look(?h)&        # rejected: `?Holder` holds `{Shape}` ...
```
This was probably accepted on main as well. It is the class the PR claims ("each instance of a generic body that makes a task is checked"), and AGENTS says to fix the class. The fix is to check `generic_requirements` on a default's `Self` at each conformance, or at least to file it. `.frozen`, `.no_task`, and the other requirements on `Self` may have the same gap.

### 2. should-fix: a `pub` generic's contract leaks through a private generic that crosses
`pub fun outer[U](x: ?U)` calling the private `spawn[T]` (whose task crosses) is accepted in lib. A user's `lib.outer(?n)` with `*Node` gets an error about `lib.spawn[*Node]`, an internal of lib (mod2/). Had `outer` made the task itself, `U` would be checked by its bounds and the task made local. `apiOf(.task) == null`, so `checkBoundedBodies` never judges the requirement by `U`'s bounds, and `satisfies(U, .task)` is true for any type variable. A better rule: when the instance argument is a type parameter checked by its bounds, decide with `boundBlocker`, so the error lands in `outer` ("state `Sends`/`Syncs`"). This is not a soundness hole: the instance is still checked.

### 3. should-fix (owner decision): a generic type is rejected for a method it never calls
In n4.rig, `obj Box[T]` has `run` making a task with `@x`. `Box(x: *Node(v: 1))` followed only by `b.get()` is rejected at the constructor. Type-level requirements are checked at every instance of the type, which is the existing convention, but on main this program was accepted and harmless. Together with "a body whose task crosses takes no `*Node`", this rejects programs a release accepted, beyond the forms listed in CHANGELOG. AGENTS requires a one-line note and a migration script to Trig before merge. The PR body should say whether that was done.

The error also gives no way out. `T = *Node` in an unbounded crossing body has no remedy except a bound without `Syncs`, which makes the task local as a side effect. Suggest naming that remedy in the message, or record whether per-instance local/crossing could be a fact (Zig comptime can choose `spawn` or `spawnLocal` per instance).
