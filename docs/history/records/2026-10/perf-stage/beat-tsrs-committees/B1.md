# B1: why Rig's code runs more instructions per call than rustc's

**Method.** pup, core 9, ts-pattern, one checker. Precise samples and LBR call counts, then hand edits of the emitted Zig, rebuilt. An unedited rebuild runs the original's 12.7505G; every variant's output matches. Data: `B1-data.txt`.

## Instructions per call

| function | Trig | tsrs |
|---|---|---|
| mapper_map / TypeMapper::map | 73 | 55 |
| instantiation (iTWA + gOTI + could_contain worker), total | 1572M | 962M (one worker) |
| recursive_type_related_to | 255 | 124 |
| is_related_to_ex | 104 | 104 |

**mapper_map's 18 extra instructions:**
- frame setup, 7 (frame pointer, more saved registers)
- index tests, 6
- spills, 4
- scheduler hook, 4
- slot casts of u32 fields, 4

**find_active_mapper's loop** runs 13 instructions a turn against tsrs's 7:
- turn counter, 2
- index test, 2
- list pointer reload, 1 (`sched.tick()` is a call inside the loop)

## Measured (ts-pattern instructions)

| edit | change |
|---|---|
| `noalias` on all 1,897 `self: *Checker` | −0.004% |
| `turn()` (loop hook) made a no-op | −5.2% |
| `tickCall()` (call hook) made a no-op | −5.2% |
| inline guard heads, 4 functions | −3.6% |
| `-fomit-frame-pointer` | −2.9% |
| the last four together | **−16.4%**: 45% of the gap to tsrs (cycles −9%, untimed) |

**noalias does nothing for Trig**, although 23k functions change:
- Hot functions pass `self` into calls, so fields are reloaded anyway.
- Zig gives `*T` no `dereferenceable`, so loads can't be hoisted past calls (checked in the IR).
- Loop data sits in buffers reached through `self`, which `noalias` doesn't cover.

Keep the queued round for std.json.

## Fixes, ranked

1. **Scheduler hooks: up to 10.3% (Rig runtime and emit; medium cost).** Two sound designs, each keeping the yield guarantee:
   - A counted loop charges its trip count at entry and, while that fits the remaining budget, runs a copy with no hook. In that copy LLVM can hoist loads and drop index tests.
   - Place one `tickCall` on each call cycle (a feedback vertex set of inlining.zig's call graph) instead of 1,725.
2. **Guard heads: about 7% (3.6% measured on 4 functions).** A function on a call cycle that starts with early returns becomes an inline head plus a `noinline` rest. This is LLVM's partial inliner, which Zig's pipeline lacks; tsrs does it by hand (checker_11.rs:1263-1313).
   - Trig, now: `inline fun` head plus `called fun` worker for the ~15 functions listed in the data file (small cost).
   - Rig, later: the same split in inlining.zig (medium cost).
3. **Frame pointers: 2.9% (Rig, one flag).** Zig's ReleaseSafe keeps them, so 4,222 of 4,228 functions set up `%rbp`. Owner decision: traces would then need DWARF unwinding.
4. **Small:**
   - Trig: TypeId fields in the mapper record (0.35%).
   - Trig: a counted reverse loop in find_active_mapper.
   - Rig: `rig.alloc.heap` is noinline (9.7M calls, 0.5%).

**Not causes:** switch lowering, error slots (none), struct returns (in registers). Index tests: proving-checks.
