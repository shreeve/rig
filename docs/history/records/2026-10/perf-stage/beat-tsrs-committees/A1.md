# A1: hash tables

Evidence: tsrs source, t.data annotate, and tg.script samples by first Trig caller, scaled to 1,875M. Caveat: tsrs's `PackedMap::get` is inlined (packedmap.rs:72), so the 842M figure leaves its gets out.

## 1. tsrs's tables
All use hashbrown 0.17 (SSE2 groups of 16 tags, at most 7/8 full) with Fx (one multiply).
- **Relation:** each slot is one u64 holding a 58-bit key and 6 result bits (relater_types.rs:116-150, relater_1.rs:36-80).
- **PackedMap:** 20-B slots, hashed by the key's own `lo` (packedmap.rs:17-21).
- **Mapper cache:** the key is the type id times an odd constant; nothing is probed when the mapper is new (checker_11.rs:1356-1419).
- **Instantiations:** one table per target, with 4-B slots and argument lists compared by value (types.rs:2341).
- **SymbolMap:** 8-B entries searched linearly up to 16, a Bloom filter, and presized tables (symbol.rs:324-560, checker_10.rs:2281).

Only SymbolMap keeps an order.

## 2. Rig's Map
A Map is 104 B, made of four Lists: `es` (24-B entries for a CacheKey), `hs`, `tags` and `at`. A lookup reads three dependent arrays (`tags`, `at`, `es`).
- **Hashing:** a CacheKey costs 4 serial `mulx` (runtime.zig:1338-1393), about 60% of `put`'s self time.
- **Per operation:** a hit takes about 85 instructions against hashbrown's 20; a miss about 70 against 12; a new key about 240 against 35. A new key is hashed twice and probed three times.
- **Growth:** about 60% of `grow` is `Table.reset`, which pushes zeros one slot at a time.

## 3. Trig's workloads (share of the 1,875M)
| workload | Trig | tsrs |
|---|---|---|
| Mapper caches, 460M | 104-B Maps moved on each push and pop (189M); 4-mulx hash | pooled 32-B tables; free hash |
| Symbol tables, 440M | not presized (grow+add 205M) | 8-B words, presized |
| Instantiations, 330M | one global 24-B-key Map, plus a Set (37M) | per target, 4-B slots |
| Relations, 240M | about 37 B per entry | one u64 per slot |

## 4. Ranked changes (instructions on ts-pattern)
1. **Rig:** fill `Table.reset` with one bulk zero. About 180M; tiny.
2. **Trig:** keep the mapper caches on a stack indexed by depth cleared in place (Go's way). About 150M; tiny.
3. **Rig:** hash an object of 2–3 words with one or two wymix multiplies. About 120M; small.
4. **Trig:** use one-word keys: `Map[U64,U32]` for relations and `Map[TypeId,TypeId]` for mapper caches. About 100M; small.
5. **Trig:** presize `instantiate_symbol_table` and `clone_table`. About 80M; tiny.
6. **Trig:** give each target its own instantiation table and drop `has_instantiations`. About 100M; medium.
7. **Rig:** have `find` return the free slot, so an insert probes once. About 30M; small.
8. **Rig:** change the lookup layout to a u64 slot holding 32 hash bits and a 32-bit index, or to inline slots with a List keeping order, and compare tags with SIMD. Still ordered. About 60M, mostly cycles; medium, after the trace and the survey.

**After overlap, about 700M (5%).** Changes 1, 2 and 5 come first.
