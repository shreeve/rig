# B2: where tsrs does less work for the same answer

M = instructions on ts-pattern (`t.data`, `r.data`, `tg.script` chains). All items are Trig-side and exact.

## Ranked briefs (Trig: adopt tsrs's lessons)

1. **Member listing in one pass** (−450 to −550M; low cost). `get_named_members` (members.rig:14-50):
   - it copies the table (`table_entries`);
   - it tests named and contained twice per entry, re-reading every container declaration each time;
   - it sorts through a closure, re-reading file and pos on every comparison.

   tsrs computes the keys once (utilities.rs:479). **Brief:** walk the table by index. Test each entry once, against the container's ranges computed once. Give each symbol a U64 key (no declaration, file, pos), check in O(n) whether the keys are already sorted, and send only tied keys to `compare_symbols`. Exact: total order, Sym ids unobservable.

2. **Inline fast paths, worker in `rarely`** (−250 to −350M; low cost). Trig's self cost is about 726M:

   | function | Trig self |
   |---|---|
   | `could_contain_type_variables_worker` | 231M |
   | `get_reduced_type` | 219M |
   | `get_apparent_type` | 139M |
   | `get_type_items_instantiation_key` | 137M |

   tsrs's flag tests are inline (checker_11.rs:1263-1291, 553, 702, 867). Verify `inlining.decide` inlines them.

3. **Recursion identity kept on each stack entry** (about −150M; low cost). Trig recomputes it for every entry on every push (relater.rig:73-105, about 200M). tsrs keeps it per entry (relater_1.rs:1577-1680, shadow-checked).

4. **Active-mapper caches by depth** (−120 to −170M; low cost). `ListOf(Map).push` costs 189M: Trig moves a four-List Map between two Lists (members.rig:2994-3010). Go reuses the slot in place. Keep one List and a depth counter (tsrs checker_11.rs:1440).

5. **Instantiation tables per target** (−150 to −200M; medium cost). Trig keeps one global Map plus a `has_instantiations` Set (members.rig:3234). The Set probe costs 42M; the Map's find, grow and add_entry cost 282M. Go and tsrs keep tables on the target (checker_11.rs:1801). First replace the Set with an object-flag bit, then measure per-target tables against RSS.

6. **Object/Function fallback filter** (−100 to −150M; low cost). `get_property_of_type_ex` costs 202M in Trig against 57M in tsrs. tsrs skips the fallback through `may_be_augment_member` (checker_09.rs:2870, 3004); Trig can use a `Set[Atom]`. Also, `get_unmatched_properties_worker` should read the source table once per walk.

7. **Presized member tables** (−80 to −100M; very low cost). Table grows cost 119M, from `resolve_object_type_members` and `add_inherited_members`. Reserve the known count.

8. **No copies on hot reads** (−60 to −120M; low cost). `context_inferences` copies the list on every inference-mapper call (inference.rig:1593); loop by index instead.

9. **Smaller items:**
   - a maybe-stack linear scan for 32 keys or fewer (−30 to −50M);
   - a pending alias, with no TypeAlias record on cache hits (checker_11.rs:2596; about −30M plus memory);
   - union merges U1-U3: `compare_types` costs 122M against 24M, measure calls first.

**Total:** about 1.4 to 1.9G of the 5.08G gap, with no unproven hints.
