# Signal preemption on the Mac (arm64 macOS), step 1 and the port (2026-11-05)

The owner approved the Mac port of signal preemption ("Yes, start the port"). The design is docs/history/records/2026-11/panels/loop-split/preemption.md §2: signals as on Linux, and a trampoline that returns by a reserved register, x15 (`+reserve_x15`), as Go's returns by R27. The order of work: (1) a probe of Darwin's signal latency and the cost of reserving x15 with preemption off, reported before the port if over 0.5%; (2) the port behind `RIG_PREEMPT=signal`; (3) the section audit and the preemption scripts on the Mac; (4) Trig, signal against default.

Machine: Apple M5 (4 P-cores, 6 E-cores), macOS 27.0.1, Zig 0.17.0. Branch `preempt-mac`, from `preempt-locks` (#972) with main merged.

## 1. The probe

A Zig program (kept in this record's data, `probe.zig`): one thread runs work that keeps sixteen integer and eight float streams live; another sends it SIGURG by `pthread_kill` about every 50 µs and spins until the handler has run. The handler records the time it runs (`cntvct_el0`, 24 MHz, both threads), then rewrites the signal context as the port does: the stopped pc at the stack pointer, 128 bytes (the red zone) and a 16-byte slot below it, and pc set to a trampoline. The trampoline saves x0-x17 but x15, fp, lr, NZCV, FPSR, FPCR and q0-q31, calls a function that records its time, restores them, and returns by `ldr x15, [sp]; add sp, sp, #144; br x15`. The whole program is built with `-mcpu=native+reserve_x15`. At the end the work is recomputed with no signals, and the two results must match.

| what | median | p90 | p99 |
|---|---|---|---|
| `pthread_kill` to the handler, three runs of 20,000 | 78-85 µs | 87-125 µs | 146-280 µs |
| `pthread_kill` to the trampoline's call | 89-97 µs | 97-140 µs | 161-326 µs |
| Mach `thread_suspend` returning (the alternative) | 191 µs | 328 µs | 709 µs |
| suspend, get and set the state, resume, to the trampoline's call | 422 µs | 635 µs | 3.3 ms |

- **The rewrite is sound.** 20,000 signals, 20,000 entries into the trampoline, every result equal to the unsignaled one, in each run. At three QoS classes (user-interactive, user-initiated, utility) the latency was the same.
- **The handler must run on the alternate signal stack.** Without `SA_ONSTACK` the kernel puts the signal frame just below the stopped stack pointer, where the handler then writes the return slot; `sigreturn` fails and `_sigtramp` traps. The runtime's workers have their own (`AltStack`), and the handler already refuses to run on the fiber's stack (`cramped`).
- **Delivery is slow: about 80 µs**, against a few µs on Linux. A signal to a thread running on another core waits for that core to look for pending work. The likely cause, not checked in the kernel's source, is that macOS on Apple silicon defers the interrupt between cores. Mach is worse: suspending alone takes 191 µs. So signals stay the mechanism.
- **What 80 µs means.** At the 10 ms slice, it is under 1% of the slice. A woken task waits for the monitor's period (50 µs while work waits) plus delivery: about 0.13-0.2 ms on the Mac. The yield checks hand over in far less, so the `hog` row is where it shows.

## 2. x15 reserved, with preemption off

Trig (origin/main 49ffa44) built as tests/lib.rip's release pack builds it, by the same `bin/rig`, once as it is (base, and a copy of it, the A/A arm) and once with `-mcpu=native+reserve_x15` added to every `zig build-exe` (a wrapper named as `ZIG`). The six projects at one checker, 30 interleaved rounds, shuffled per project, through `tools/low`; the load average was 9 to 36 (other sessions building), so cycles are noisy and instructions decide.

- **x15 is gone from the code:** Trig's uses of x15 or w15 drop from 16,596 to 15, all in Zig std's own `asm` that saves every register (`std.debug`), outside the program's section.
- **Instructions, fewest against base:** x15 0.29% more on mitt, 0.18% neverthrow, 0.01% fewer tiny-invariant, 0.03% more superstruct, 0.05% zod3, 0.03% ts-pattern. The A/A copy, the same binary, reads 0.31%, 0.33%, 0.01% fewer, 0.07%, level, level: the kernel's share of the count moves by that much on the short projects. x15 against its A/A is within 0.15% everywhere.
- **Paired cycles** (median per-round ratio): x15 0.25% fewer to 0.85% more; the A/A arm 0.67% fewer to 0.77% more. Inside the noise.
- **Output:** one digest per project across all three arms, in all 540 runs. Peak memory level.
- **bench/tasks** (10 rounds, its scale and five rows): instructions 0.47% fewer to 0.03% more, cycles 0.53% fewer to 0.08% more; the five rows' wall times swing as the A/A arm's do (`hog` 41% slower in the A/A arm, a run of one 3.6 ms row under load).

**Below the 0.5% bar**, so the port goes on with the reserved register, and the `brk` fallback is not needed.

## 3. The port

What the Mac needs beside the Linux code (`src/sched.zig`):
- `preempt_built` holds on arm64 macOS when the target has `reserve_x15`; `bin/rig` passes `-mcpu=native+reserve_x15` to a program built to be preempted there (`Package.zigFlags`).
- The handler reads pc and sp from Darwin's machine context (a pointer at byte 48 of `ucontext_t`; sp at 264, pc at 272), and writes the return slot 16 bytes below the red zone.
- The arm64 trampoline, `preemptEntryArm`.
- `programCounter` by `adr`; `sleepNs` by libc's `nanosleep`.
- `poll` reads a kqueue on this macOS (a pipe's event shows as `POLLIN`, and the event stays queued), so `serviceDue` is unchanged.
- A worker that ends is no longer signaled: the monitor signals a worker's thread holding that worker's `signaling` lock, and the worker clears its `tid` under it as it leaves (`leavePreempt`). `pthread_kill` on a thread that has ended is undefined; this was open on Linux too.

### The section's bounds on Mach-O

The design had the runtime read `__TEXT,__rig_text` with `getsectiondata`. Zig 0.17's own Mach-O linker (it cannot link Mach-O with LLD) puts every input section that holds instructions in `__TEXT,__text` (`initOutputSection` in src/link/MachO/Atom.zig: `if (sect.isCode())`). The assembler marks any section it writes instructions to `S_ATTR_SOME_INSTRUCTIONS`, so no spelling of the section avoids it. Every spelling tried (`__TEXT,__rig_text`, with `regular,pure_instructions`, another section name, another segment) linked into `__text`.

A section marked as holding no instructions is kept: an object whose `__rig_text` flags are cleared to `S_REGULAR` links into a section `__TEXT,__rig_text` of its own, executable since it is in `__TEXT`, and the code runs. So on arm64 macOS `bin/rig` builds a program built to be preempted as an object (`zig build-obj`), copies it with that section's flags cleared (`keepCodeApart`), and links the copy (`buildApart`; a split debug build does the same to each unit). The runtime finds the section through dyld's first image (`_dyld_get_image_header(0)`); `@extern` of `_mh_execute_header` gives a wrong address under Zig's linker.

The cost: Zig's linker writes a data symbol's stab (`N_STSYM`) for a function in that section, not a function's (`N_FUN`), so a panic's stack trace shows `???:?:?` for the frames of the program's own code, where the same program built without the option shows `__rig_main.zig:9`. Unwinding through them works (the trace goes on past them). lldb still finds their lines.

**The owner's decision** (through Rig, "Follow your recommendation here"): the lost lines are accepted while `RIG_PREEMPT=signal` is an option on the Mac. **Fixing them is a condition of any Mac default-on.**

**The fix's likely size: small.** `dsymutil` reads the debug map, stabs of either kind, and writes a `.dSYM` that holds the section's functions; Zig's stack traces read a `.dSYM` beside the executable. With one, the same program's trace shows `deep` at `__rig_main.zig:9` and no `???`. On Trig built with the option, `dsymutil` takes 2.8 s and 1.5 GB at its peak, and writes 115 MB. So the fix is to run `dsymutil` after the link in `buildApart` when it is on `PATH` (it comes with Apple's command-line tools, which Zig does not need), and to keep the `.dSYM` with a kept build (`keepBuild`, `reuseBuild`): about 20-40 lines. Without the tools the trace stays as it is now. The other routes are larger: rewriting the executable's symbol table to turn the stabs into function stabs (the string table and `__LINKEDIT` laid out again, and the ad-hoc signature made again: hundreds of lines), or a symbolizer of Rig's own in place of Zig's for Mach-O.

### It runs

- A program whose only worker runs a task that spins until a second task sets a flag (`starve.rig`, `task.workers(1)`) hangs without preemption; with it, one signal stops the spinner, the setter runs, and it prints `0 1`. Release (`rig run --release=fast`, `rig build`) and debug (`rig run`, split into units) alike.
- bench/tasks built with the option runs all five benchmarks with the same checks.

### The section audit on Mach-O

test/cli/preempt_section.sh also builds bench/tasks and bench/actors natively on arm64 macOS and reads the object `bin/rig` links, whose `__rig_text` holds the section's code and its debug lines. Beside the scheduler and mailbox checks the x86 build has, it fails when an instruction in the section uses x15 or w15, or when the section has a TLVP relocation (a thread-local read). The x86 build now also fails on `%fs:` in `rig_text`.

Its first run found thread-local reads in the section, and the x86 build has the same: 13 `%fs` reads in bench/tasks. They were three problems in the Linux code, fixed on preempt-locks (#972, locks-2026-11-05.md, "Three more found by the Mac port's audit"): `task()`'s thread-local carried into the program's code by LLVM, Zig's allocator's slot lock inlined there, and a worker's thread signaled after it ended. With them the audit passes on both targets. Each of its patterns was checked against the disassembly it reads (535 uses of x10-x14 and x16 matched; the same text with x14 renamed x15 caught).

A note on the check's first form: `! objdump ... | grep -q TLVP` passed with 11 TLVP relocations present, since `grep -q` stops early, `objdump` dies of SIGPIPE, and `pipefail` makes the pipeline fail, which `!` turns into a pass. It reads a file now.

### test/cli/preempt.sh on the Mac

It passes (9 s). It gains a case that preemption runs: a task that spins on the only worker until a task queued behind it sets a flag, with no local task; it prints `0 1` with and without the option, and where preemption is built (Linux x86-64, arm64 macOS) the scheduler's counts must show a task preempted (`RIG_SCHED_STATS=1`).

### The trampoline as a frame

Rig's review of 885592a45 found the trampoline's frame pointer naming {x17, the stopped x29}, not a frame record, so a walk of frame pointers through it (a panic's trace from `preempted`, lldb, a sampling profiler) read x17 as a frame. Pointing x29 at a record of the stopped frame pointer and pc was not enough: Zig's unwinder reads unwind information first, and a naked function's is that of a function with no frame, whose return address is the link register, which `bl` had pointed into the trampoline itself; a trace showed the trampoline 14 times and stopped.

Now the handler writes the record just below the stopped stack pointer, after moving the 16 bytes of the red zone it covers to the slot below the red zone, and the trampoline puts them back before it returns. Its call frame information makes its frame's canonical address the stopped stack pointer, takes the record's two words as the stopped x29 and its return address, and names x15 the return address's column, with x30 saved apart, so a stopped function whose link register is live keeps its own. A trace from `preempted` (`RIG_PREEMPT_TRACE=1`, which prints the first preemption's) goes through it into the stopped code and on to `fiberMain`, in debug and release builds; preempt.sh checks it in a debug build. bench/tasks with a 100 µs slice (1,100-1,250 preemptions a run) and bench/actors give their checks as without the option. Trig's numbers in §4 are from before this change, which adds four instructions and two stores to each preemption, not to the program's code.

The x86 trampoline had no call frame information of its own either, and its frame record read the flags as its return address (`rbp` pushed below them). It now pushes `rbp` first, onto the stopped pc, so {stopped `rbp`, stopped pc} is the record `rbp` names, then the flags; its call frame information gives the stopped stack pointer as its frame's address (the entry's plus 136) and the slot at entry as its return address. A stopped x86 function keeps its return address on its own stack, so no column of its own is needed. Checked in an x86-64 Linux build cross-compiled on the Mac: the `.eh_frame` rows (CFA = RSP+136, RIP at CFA-136; RSP+144 and RBP at CFA-144 after the push; RBP-based after the move; RSP+136 again before the return) and the instructions (`leaq -0x50(%rbp)` back to the nine registers and the flags). A trace through it is not run here, since a Linux debug build is not preempted and the Mac runs no Linux; pup's checks after the merge run preempt.sh there.

## 4. Trig, signal against default

The same Trig (49ffa44), built once more with `RIG_PREEMPT=signal` by the branch's `bin/rig` (`__rig_text` 8.5 MB), against base and the A/A copy from §2. The six projects, 20 interleaved rounds at one checker and 20 at tsc's default of four, shuffled per project, through `tools/low`; the load average was 4.2 to 4.4. ## Conditions before preemption is on by default on the Mac

1. **Stack traces** (the owner's condition): the lines of the program's own frames, by `dsymutil` after the link (§3), or another way.
2. **The woken task's wait** (preemption.md §4, step 2, for Linux too): with delivery at 80 µs, a woken task waits 0.13-0.2 ms behind a running one on the Mac; bench/tasks' `hog` row is where it shows.
3. **Linux aarch64** shares the trampoline but not the context's layout, and is not built.
