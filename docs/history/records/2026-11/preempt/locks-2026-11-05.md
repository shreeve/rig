# Preemption: locks taken apart from the program's code go uncounted (2026-11-05)

The default-on round's step (c'), after #970 (`ops-2026-11-05.md`). Under `RIG_PREEMPT=signal`, each spin lock counts itself (`holdOff`, `holdOn`): two calls, never inlined, that each read the thread's worker. The count keeps a signal from stopping a fiber that holds a lock in the program's own code (`rig_text`). A stubbed build bounded what the counts cost: all of `contend`'s 5.9%.

## The rule

A signal stops a fiber only where its program counter lies in `rig_text` (`onPreempt`). A lock taken and let go within code outside that section, with no call into the program's code while it is held, needs no count. A signal that comes while the lock is held finds the program counter outside the section, and the handler returns.

Such a lock is `SpinLock.lockApart` and `unlockApart`, named for the entries it serves (`XApart`, never inlined into the program's code). Three things keep it sound:
- **The places it is taken:** only in the body of an entry the program reaches through a call that is never inlined (`sendApart`, `takeApart`), or in the scheduler's own lists, reached only from such bodies, from the workers' loop, and from the monitor.
- **A static check:** `test/cli/preempt_section.sh` fails if any line of `lockApart`, `unlockApart`, or the mailbox entries' bodies lies in `rig_text` of bench/tasks or bench/actors. The first two are not in sched.zig's allowlist; the bodies are named in tasks.zig's list.
- **A runtime check:** in a safe build with the option, `lockApart` reads its own program counter (`leaq (%rip)`, inlined wherever the lock is) and panics if it lies in `rig_text` (`mustNotBeInCode`). The check is the same one `me()` makes, for code the optimizer may inline.

A lock taken in the program's code and let go in an entry's body, as `sleepOn` lets go its caller's lock, stays counted at both ends.

## What changes

- **The actor's mailbox:** `send` (put a call in the mailbox) and the runner's take of the next call become `sendApart` and `takeApart`. Each is one call, never inlined, that takes the actor's lock uncounted. Before, `send`'s body was inlined into the caller's code in `rig_text`, so every call to a busy actor paid for two counts.
- **The scheduler's lists:** the global queue (`Global`), the sleeping workers (`Sleepers`), and the timers (`Timers`) take their locks uncounted. Their code is reached only from the scheduler's entries, the workers' loop, and the monitor, and never lies in `rig_text` (the allowlist).
- **Unchanged:** built without the option, `lockApart` is `lock` and each entry is its body, so the instructions are the same as before.

## The failing case

On main cf6a362a6, bench/actors built with the option and cross-compiled for x86-64 Linux puts 5 lines of tasks.zig's `send` in `rig_text`. The new check in `preempt_section.sh`, that no mailbox entry's body lies in `rig_text`, fails there; on the branch it passes.

The check now also runs on the Mac. It cross-compiles the two benches for x86-64 Linux from the package `rig emit` writes, then reads them with the system's `objdump`, which is LLVM's.

## What the branch shows without timing (the Mac)

- **Counted locks in bench/actors' `rig_text`:** from 7 calls of `holdOff` to 6. `send`'s is gone. The 6 left are on rare paths: the deadlock walk's lock in `unblock`, taken only while a walk runs; `settleLeftCalls`; the output and allocation locks; and the clock.
- **The runtime check:** a ReleaseSafe build has it at the head of `sendApart`, a `leaq (%rip)` compared with the section's bounds.
- **Off:** bench/tasks and bench/actors, built for the Mac without the option, have the same instructions as main's, with addresses masked.

## To measure (pup, in a window Rig gives)

The rows of bench/tasks and bench/actors, measured as `ops-2026-11-05.md` measured them: off, main on, and branch on, on 2 workers on P-cores 6 and 8, the fastest of 9 interleaved rounds. The expectation is that `contend` moves toward level with off, as the stubbed build showed, and no row gets slower.

## Three more found by the Mac port's audit

The Mac port's audit (mac-port-2026-11-05.md) reads the section's relocations and found thread-local reads there; its x86 counterpart, `%fs:` in `rig_text`, finds the same on Linux: 13 in bench/tasks, cross-compiled from main's code. The audit now fails on any, and passes on the branch.

- **`task()` outside a fiber read its thread-local inline.** Under preemption it calls `threadTask`, never inlined, but LLVM takes a thread-local's address for a constant and propagated `threadTask`'s result into each caller, so the call vanished and the `%fs` read sat in the program's code (speculated before the test of `sched.current()`, its value then discarded on a fiber). An empty `asm` hides the address, and `threadTask` stays a function of its own.
- **Zig's allocator inlined into the program's code.** A task's waiter frees the task's record, and a group of tasks makes and frees its `Wakeup`, through `std.heap.smp_allocator`, whose `free` and `alloc` read a thread-local (the thread's slot) and take that slot's lock, uncounted. In a program built to be preempted these are now calls never inlined (`Full.destroyApart`, `Wakeup.createApart` and `destroyApart`), as the mailbox's are.
- **A worker that ended could still be signaled.** The monitor reads a worker's thread and calls `pthread_kill` on it, which is undefined once that thread has ended. Each worker's thread is now signaled under that worker's `signaling` lock, and a worker clears its thread under the same lock as it leaves (`leavePreempt`). No case shows this one: the window is a few instructions as the program ends.

Built without the option, bench/tasks and bench/actors have the same code as before these three (their `__text` compared with addresses masked).
