Views and owners

Four words: read view write view for the holder, read-only off-limits for the owner.

1. Two sides of one hand-over

The sigil sits on the owner. The holder gets a view. The owner is limited while the view is in use.

2. Two sigils, two kinds of value

Only two sigils make views: ? and !. What they leave the owner depends on one thing, the type of the value viewed, not who holds the view. Types come in two kinds:

?v read view!v write view
An ordinary value
Int, String, List, Map, your own objects		read-onlyoff-limits
A value that changes only through its own calls
Cell, Signal, channel, actor, an object holding a Cell. It always lives behind *.		read-onlyread-only
Here the owner c is a handle (*Cell). Read-only holds the handle still: no one may assign, move or drop it. What it shares still changes, but only through its own calls (!c.set(5)), as CORE sentence 9 says of all shared storage. A write view of the handle itself (w = !c with no type gives a !*Cell, which can point c elsewhere) is an ordinary write view: off-limits.

For an ordinary value, the view decides: reading leaves the owner read-only, and writing shuts the owner out. For the second kind, the sigil makes no difference: both leave the handle read-only. The value changes only by its own calls, one step at a time, so no view can be left looking at something gone. The only thing it must be kept from is being replaced or freed, and read-only does exactly that.

3. Which view leaves the owner how

Each kind of view fixes the owner's state. There are three paths, and only one is an exception.

The exception covers a value that changes only through its own calls: a Cell, a Signal, a channel, an actor, or an object holding a Cell. Many write views of it may live at once, and each call is one step.

For a Cell, read-only holds the handle c. The Cell it shares still takes its own calls (!c.set(5)). The rows for a write view, assigning, moving and dropping apply to the handle.

5. How long it lasts: until the view's last use

The state starts where the view is made and ends at the view's last use, not at the end of the block.

6. Your question: one qualifier each?

Almost, but the qualifier sits on the owner, not on the view. A view is just a read view or a write view. It carries no second word. What follows from it is the owner's state:

  • a read view always leaves the owner read-only;
  • a write view leaves the owner off-limits, except for a Cell and its kind, which it leaves read-only.

So you choose one of two views, and the owner's state follows. It is never a separate choice, so you only learn three paths, not four combinations.
