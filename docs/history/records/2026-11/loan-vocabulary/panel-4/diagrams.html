Places and views

The words settled so far, and cells as the compiler actually treats them.

1. The words

WordMeaning
placea variable, a field, or an element: what a sigil is put on
read view
write view		what ? and ! make; a view has no other qualifier
read-onlywhat every view leaves its place: it may be read, copied and given views, but not changed, assigned, moved or dropped
unusablewhat a write view of an ordinary value leaves its place: it can't be used at all, as after a move, but it comes back by itself at the view's last use
cella Cell, or a value that holds one: a Signal, a channel, an actor, or an object with a Cell field. It lives only behind * and changes only through its own calls

2. The rule

Any view leaves its place read-only until its last use.

A write view of an ordinary value goes further: its place is unusable until the view's last use.

An ordinary value is anything that isn't a cell.

In !p.items.push(1), the ! covers the whole path: a write view of p.items, handed to push as its self. p.name stays free.

3. Every view leaves its place read-only

While the view is in use, the place may…readcopygive viewschange, assign, move, drop
read view✓✓✓✗
write view of a cell✓✓✓✗
write view of an ordinary value✗✗✗✗

The last column is ✗ in every row: that column is read-only, and every view gives it. Only a write view of an ordinary value goes further, because it could leave the value half-changed while someone reads it. A Cell changes only by its own calls, each one complete step, so it never needs to stop reads.

4. Two sigils, two kinds of value

What a view leaves its place depends on the kind of value the view sees, not on who holds the view.

The view sees…?v!v
an ordinary value
Int, String, List, Map, your own objects		read-onlyunusable
a cell
Cell, Signal, channel, actor, an object with a Cell field, std's shared.Map		read-onlyread-only

The second row is one rule for all six members. 180 programs, six members by three kinds of view by ten acts, gave the same verdict for every member.

5. How long: until the view's last use

6. A cell: the place holds a handle

A cell lives only behind *. So its place never holds the cell itself; it holds a handle.

While any view of c is in use, c may…
be read; give +c, ~c, ?c, another !c; take its own calls (!c.set(5))✓
be reassigned, moved, dropped, or handed over as the handle itself (a !*Cell parameter)✗

"Holds" means holds directly. An ordinary object with a handle field (c: *Cell[Int]), kept by value in b, is an ordinary value: !b leaves b unusable.

7. How long each member's view lasts

The rule is the same for all six; only "until its last use" takes a different shape.

The view is made by…It lasts…
a call: !c.set(5), !ch.send(v), !a.add(x)for the call
a binding: w: !Cell[Int] = !cuntil the last use of w
a task that holds self: t = (!h).bump()&until it is waited for (>t) or dropped
a select's arm: !ch.on_recv()until the select returns
an actor's call made a task: !a.add(x)&not at all: the task holds its own count of the actor, not a view

8. Open: the untyped w = !c

The same line means two things, depending on where c lives and whether a type is written:

w: !Cell[Int] = !c     a write view of the Cell    → c is read-only
w = !c                 a write view of the handle  → c is unusable
                       (it may point c at another Cell: w = *Cell(9))

When c is a *Cell parameter, which can't be assigned, the untyped line already picks the Cell. A trial build that always picked the Cell when no type is written broke 11 tests. 7 of them are real: swap(!a, !b) of two Cell handles (6 tests) and a generic !T (1). Those would need another spelling.

9. Smaller findings

  • Signal isn't counted as holding a Cell, so a Signal by value is accepted as a parameter or a List element, where a channel or actor is refused.
  • A !Chan[T] can send and receive, but it isn't accepted as a select arm, which takes only the handle.
  • ?Actor[T] and !Actor[T] are accepted as types but have no methods.
  • Messages must name the view by the sigil written. The compiler records a Cell's !c as a read loan, and today's note says "lent to read here" under !c.
