## Summary
v0.2.1 accepts these programs, and they either corrupt memory or emit Zig that doesn't compile. Each fix closes a whole class, by type and recorded fact, not by syntax.

- **A store through a write loan was lost when nothing named the target.**
  - One rule, `storeThroughLend`, now serves calls and assignments alike.
  - A write receiver stores through its place's variable, or through the write loans its value carries.
  - An assignment target that starts from an unnamed value (`(!h).r`, `wrap(!h).r`, `wv(!v)[0].r`) stores through that value's write loans.
  - Before, `wrap(!h).keep(?s.t)`, `(!a if c else !b).keep(…)` and `(!h).r = ?s.t` left `h` holding a view of a freed value.
- **A part was moved out through a view.**
  - Whether a path passes through a view or a handle is now decided by the type of each value on it (`viewOnPath`).
  - Now rejected: `<(!s).items`, `<(?s if c else ?t).items`, `<wrap(!s).items`, `<(!p).items`, `<(?v)[0]` and `<(?h).items`, as `<v.items` through a view always was.
  - Taking an optional through a write view (`<(!s).o`) still works.
- **Constants were lent to write.**
  - One check, `isConstant`, decides by meaning. A constant is a literal, `none`, a function, a module's constant, a type's member (payload-free variant, error value, number limit, type function), an operator over constants, or a value every branch of which is a constant. All of these count from any module.
  - `!false`, `!"abc"`, `!Color.red`, `!E.bad`, `!Int.max`, `!f`, `!P.origin`, `!lib.Color.red` and `!lib.twice` now get one message, "cannot lend constant `X` to write", instead of emitting Zig that fails.
  - A local binding that holds a function may still be lent to write.

These holes were found by the independent reviews of the seam 2 round. Seam 2 itself is stopped for redesign, and will be rebuilt on top of these fixes.

## Core conformance
- **Sentence 6:** a loan lasts while any view carrying it is used, including a view stored through a lend.
- **Sentence 2:** an owner is dropped once, and nothing is moved out of a part reached through a view or a handle.
- **Sentence 7:** a constant lives for the whole program and never changes.
- **"One classifier per fact":** where stores land, whether a path goes through a view, and what is a constant are each decided once.

## Behavior changes
The programs above go from accepted to rejected; each was unsafe or failed to compile on v0.2.1. Module-constant diagnostics are reworded. Equivalence against v0.2.1 (8,311 programs) shows no other change.
