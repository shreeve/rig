# Study: "mutation is never data"

Measured on `origin/main` 308585bf, 2026-10-09, in a throwaway worktree. Nothing here was merged, committed to a shared branch, or pushed.

## The verdict

1. Half of the reveal is as big as it looks. Rule 2 (a Cell lives only behind `*`) removes the whole Cell-temporary and Cell-by-value class. All 7 Critical/High Cell findings from the reviews are now unwritable, along with the `cellmut.`, `celltemp.` and `cell.` matrix families. About 260 lines of deciders and emit backstops become dead, and the per-instance interior-mutability machinery in the runtime goes too.
2. The other half is smaller than it looks. Rule 1 (a `!T` is never data) kills write views in fields, payloads, elements and type arguments. But the recurring payload-loan bugs mostly come from write views held in **locals and parameters**: `(!T)?` locals, and branches over `!T` names. Those stay legal, so only 3 of the 9 payload-loan and syntax findings become unwritable. `makesWriteView`, `headerCopiesWriteView`, `TC30`/`TC31` and the `as`/`match` binding deciders are all still reached.
3. No curated real code breaks: examples/, std/, and the README, WELCOME, STD, DESIGN and FAQ examples are unaffected. 918 of 5,586 accepted programs flip. 768 of them are tests or probes of exactly the restricted forms, 31 are real-style code fixed by one `*` per Cell or Cell-holding value, and 119 come only from the strict closure rule.
4. The strict closure rule is the costly extra. It allows a write capture only in a closure lent to a call. That flips 119 programs, including CORE L943 and SPEC L5069, and adds nothing, since a stack closure cannot escape and owned closures already cannot capture `!T`. Drop it. With that change, rule 1 is `!T` only in a parameter, a result, a receiver, a binding or a stack closure.
5. Recommendation: take rule 2 now. It is a real class kill and costs a one-`*` rewrite in ~30 programs. Take rule 1 as well for its simplicity (−~135 lines, 17 sites gone). But do not expect it to end the payload-loan rounds: those need a rule about held write views in headers. Restricting `(!T)?` to parameters, or banning branches over write views, is the next measurement.

## Setup

- **Implementation:** one pass, `typecheck.checkMutationNeverData`, run after `checkGenericInstantiations`; diagnostics are listed below. Nothing else was changed or deleted. Measuring builds also carried 63 `MNDPROBE` probes, which print to stderr and do not affect verdicts.
- **Rule 1, write views:**
  - `!T` is rejected in a struct field, an enum payload field, an array, slice or Vec element, a type argument (type instances and function instances), an array literal, and under `?` (`?(!T)`).
  - It stays allowed as a parameter, a result, a receiver, a local or header binding, and as `(!T)?` or `(!T)!` in those positions.
  - Closures, strictest version: a closure with a write capture is allowed only when lent directly to a call or called where written. Rig already keeps stack closures from escaping and keeps owned closures from capturing views.
- **Rule 2, Cell:** a type holding a Cell by value is rejected everywhere except as a `Cell[T]` field directly in a struct (whose values then exist only as `*S`). That covers locals, parameters, results, type arguments, arrays, slices, optionals and nested struct fields. A constructor of one is rejected unless written under `*`, or unless it is a bare `Cell(...)` given as a field argument. `*Cell[T]`, `?Cell[T]`, `!Cell[T]`, `?S` and `*S` stay allowed.
- **Diagnostics:**
  - `mutation is never data: field `w` cannot hold a write view (`!Int`); ...`
  - `... a type argument cannot be or hold a write view`
  - `a closure that outlives its call cannot capture a write view; ...`
  - `a Cell lives only behind a shared handle: `k` cannot have the type `Counter`; use `*Cell[T]` or `*S``
  - `... the result `C` holds a Cell by value ...`
  - `... this value of type `Counter` holds a Cell by value; make it with `*``
- **Known imprecision:** a field default `hits: Cell[Int] = Cell(0)` is flagged as a temporary. It affects only SPEC L865, which is rejected anyway for using `Config` by value.
- **Sweeps:**
  - `rig emit` (so ownership, storage and emit run, and their probes fire) over all 11,713 tracked `.rig` files in test/, examples/ and std/, plus the 359 doc examples extracted as `./test/run` does: 12,072 programs on each build.
  - The matrix (7,501 cells generated by `test/matrix.py`, checked only) ran on pup.
  - The 183 review probes: the copies in test/corpus/ where they exist (current syntax), otherwise the originals.

## Before/after rewrites (the first 5 of class (b))

Each "after" was run with `rig run` (debug, leak-checked) on the experiment build, and its output matches the original's expected output.

1. SPEC L1228 (generics tour):
   ```diff
   -  log = Cell[Vec[*Pair[Int, String]]](value: Vec())
   +  log = *Cell[Vec[*Pair[Int, String]]](value: Vec())
   ```
2. SPEC L5613 (errors through a closure). A handle is captured by clone instead of a write capture of a bare Cell:
   ```diff
   -  total = Cell(0)
   -  each(["ab", "c"], |!total, l| total.set(total.get() + parse(l)!))!
   -  each(["ab", ""], |!total, l| total.set(total.get() + parse(l)!)) catch |e| print("failed", e)
   +  total = *Cell(0)
   +  each(["ab", "c"], |+total, l| total.set(total.get() + parse(l)!))!
   +  each(["ab", ""], |+total, l| total.set(total.get() + parse(l)!)) catch |e| print("failed", e)
   ```
3. SYNTAX L1389 (optional handles in a Cell):
   ```diff
   -  a = Cell[*Node?](none)
   -  b = Cell[Held](*none)
   +  a = *Cell[*Node?](none)
   +  b = *Cell[Held](*none)
   ```
4. test/behavior/effects/closure_propagation.rig: the same rewrite as 2 (`total = *Cell(0)`, `|+total, l|`, three lines).
5. test/behavior/std/random_in_cell.rig:
   ```diff
   -  c = Cell(random.Random.seeded(1))
   +  c = *Cell(random.Random.seeded(1))
   ```

The SPEC §10 Cell example (L4578) rewrites the same way and runs. Its `bump(c: ?Cell[Int])` still works: `bump(local)`, `bump(?local)` and `bump(?k.hits)` all compile against a `*Cell` and a `*Counter`.
```rig
  local: *Cell[Int] = *Cell(1)
  bump(local)
  k = *Counter(hits: Cell(0))
  k.hit()
```
