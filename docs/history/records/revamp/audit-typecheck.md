## LANGUAGE QUESTIONS

1. **`for x in <w` over a borrowed Vec (TC2).** The safe fix rejects it. The alternative is to give `for x in <!w` the meaning "drain the Vec in place" (Rust's `drain(..)`), which would be a new meaning.
2. **Function values as module constants (TC8).** Should `G = P.get` stay accepted, making `F = twice` accepted too for consistency? Or should neither be allowed?
3. **Aliases (TC3 and the restrictions table).** Should an alias act fully as the type it names? That covers `Byte(x)` conversions, constructing through an alias of a generic instance (`IB(v: 3)`), and imported aliases as types (`lib.M.a`, `lib.PA.mk()`, `lib.Byte.max`). TC3's minimum fix only makes the imported alias an error where it is used as a value.
4. **Compound assignment through a `!T` field** (`h.w += 1`, `h.w = 5`): should it write through, as the same statements do on a `!T` binding?
5. **Binding payload fields by name in patterns** (`.move(x: a)`), currently "not supported yet".
6. **`F32(k)` of a constant integer that is not exactly representable (TC26)**: reject, as annotation does, or round, as the runtime does?

## Biggest simplification opportunity

The file has about a dozen overlapping "what is this place, and may I write, take, or lend it" predicates: `placePath`, `checkWritable`, `checkSymbolWritable` (plus copies inside `checkSet`), `checkLendsWriteBorrow`, `hasStorage`, `isStoragePath`, `isFieldPath`, `isPlaceExpr`, `placeRoot`, `cellSettable`, `cellVecElementIn`, `copiedBindingRoot`, and `assignsIntoTemporary`. Each consumer (assignment, `!x`, take `<p.f`, `for x in !xs`, `Cell.set`, elements methods, `swap`/`replace`) combines a different subset, and TC4 exists because `synthMove` skipped one of them. Computing one `Place` descriptor once per place (root symbol and kind, first read-only or indirect step and why, a Cell-Vec element on the path, a temporary base) and exposing one `requireAccess(place, .write/.take/.lend)` would remove about 150 lines and several drifting diagnostics, and make each rule hold for every consumer. The same approach applies to the two critical bugs: `for <w` and `?? jump` each peel borrows by hand. A single `ownsValue(expr, ty)` predicate ("this node hands over an owned value, not a borrow of one"), shared with `synthPropagateNone` and `checkOptionalBinding`, would close that class. For the file size, two parts already have clean seams and could move out: the post-body passes `checkGenericInstantiations`/`checkRequirements`/`satisfies`/`checkInstanceSizes`/`FrameWalker` (7710-7983, free functions, about 275 lines), and the numeric-constant helpers (7427-7580, next to `sema.intRange`). Generic-call inference (4600-5180) is the next natural candidate, as free functions over `*Checker`.
