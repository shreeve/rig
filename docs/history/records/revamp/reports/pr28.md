This PR makes each error belong to its own error set, and makes failing name the set. Both were found by the purity review, and both come before the standard library defines its own error sets.

## Each error belongs to its set
- **Different sets never compare equal.** With `error Net { timeout }` and `error Disk { timeout }`, a `Disk.timeout` failure no longer equals `Net.timeout`, in the same module or across modules. In Zig each member is emitted as `error.@"Disk.timeout"`, and a member from another module as `error.@"mod.Set.name"`.
- **Errors print as `Disk.timeout`.** This applies to `print`, `rig test`, and a failure that leaves `main`, which now prints `error: Disk.timeout` and exits 1 after cleanup (Zig's error-return trace for `main` is no longer shown).
- **Match arms may name the set:** `Net.timeout =>`, `io.IoError.eof =>`.
- **A bare `.name` compared or matched against a caught error `e`** resolves to the one set that has it. The candidates are this file's own sets plus the `pub` sets of the modules it reaches. When the name is ambiguous, the error lists every candidate as this file would write it.
- **Module constants of an error-set type (`lib.DEF`) and aliases of error sets** work everywhere. Constants are not patterns: compare in a guard instead.

## Failing names the set
Where a `T!` is expected, a bare `.name` is always a variant of `T`. Before this, in a `Color!` function, `.missing` failed only because `Color` had no `missing` variant. Adding one silently turned the failure into a success. It is now rejected with the hint "`.missing` is not a variant of `Color`; to fail, name the error set: `E.missing`".
