This PR fixes a memory-safety hole: a value read by one argument of a call could be changed or freed by a later argument of the same call.

## The bug
`print(v, grow(!v), v)` was accepted. The first `v` was copied as a Vec struct that shares `v`'s buffer, and then `grow` pushed through `!v`. So `print` read a stale length over the changed buffer: it printed `[0] 2 [0, 7]`. If the push reallocates, the first read is a use-after-free.

The same pattern did worse with other types:
- `print(b, rebox(!b))` on a `Box` printed freed memory.
- `print(rc, reset(!rc))` read a freed handle.
- `print(v, eat(<v))` printed a Vec that `eat` had already dropped.

## The fix
A place read by value in an earlier argument keeps a read loan on it until the call ends, when the value shares storage: a Vec, Box, handle, or a struct or optional holding one. A later `!v` or `<v` in the same call is then rejected, as Rust rejects `f(&v, g(&mut v))`:

```
cannot write-borrow `v` while an earlier argument's read of it is in use
note: `v` read here: the value shares its storage, and the call uses it after its later arguments run
```

Finished copies leave no loan, so these stay accepted:
- `print(v.len, grow(!v), v)`
- a Copy struct
- `!v.push(v.len)`
