Paren-free calls are commands, not values. A line that *does* something may drop its call parentheses; anywhere a value is expected, a call takes them. This removes the spacing "sharp edge" (`b = a -1` used to call `a`) instead of documenting it, and every spacing mistake now gets a message that names the rule and shows both fixes.

## Language

- **Paren-free calls still work** as a whole statement (`print total`, `!v.push 3`), as the last argument of another command (`send encode <packet`), and as a closure body.
- **Parentheses are now required** in `if` and `while` conditions, `for … in` sources, `match` subjects, the right side of every binding and assignment form (including compound assignment and module constants), and the values of `return` and `break`.

## Diagnostics

- `if a <b`: "a sigil touching its operand is a prefix: to compare, write `a < b`; to call `a`, write `a(<b)`". Subtract, multiply, and add get the same message for `-`, `*`, and `+`.
- `x = twice 5`: "a call where a value is expected takes parentheses: `twice(5)`".
- `print total -1`, where `total` is an `Int`: "`total` has type `Int` and cannot be called; a sigil touching its operand is a prefix: to subtract, write `total - 1`". This covers inside a command's arguments, where the call reading is still legal.

## Migration

Four places changed: one behavior test that showed paren-free values on purpose, and three doc examples that warned about the old sharp edge. Nothing in `examples/` or the rest of the suite relied on paren-free values. A prototype on main found no paren-free call in any condition anywhere.
