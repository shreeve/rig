This PR settles the open language questions answered after the revamp and fixes what an adversarial review of those changes found.

## Language
- **`pass`** is a statement that does nothing: `_ => pass`, an empty loop body, `pass if cond`. It is rejected as a value, and `pass` is now a keyword.
- **Labels** are allowed only on a loop, a `match` or a `raw` block, one label each. A label anywhere else, which used to be accepted and silently ignored, is now rejected.
- **`errdefer`** is rejected where nothing can fail: a function or closure that cannot fail, a `drop` body, or deferred code.
- **Write borrows are exclusive for every type.** While `w = !n` is still used later, `n` cannot be read, even when it is a Copy value. SPEC already stated this.
- **Writing through a borrow held in a field or element.** `h.w += 1`, `h.w = 5` and `xs[0] = 9` write through a `!T` field or element. `h.w = !m` still points the field at `m`. Writing through needs write access to the struct.
- **Documented:** `F32(16777217)` rounds, as the same conversion does at run time, while `a: F32 = 16777217` must be exact.

## Fixes from the review
- **Writing through a `!T` element** emitted Zig that did not compile. It now works.
- **Loops over arrays of write borrows** (`for x in !xs` over `[N]!Int`) are rejected with a hint to loop over the indices. They used to print pointers or emit bad Zig.
- **A write borrow of a Copy value copied into a borrow position** (`h.w = w2`, `v: !Int = w2`, `[w2]`) duplicated the borrow. It now needs `<w2`.
- **A borrow stored through nested `!T` fields** is attributed only as deep as it goes. The old rule was over-strict and named the wrong owner in its message.
- **Clearer diagnostics** for a double label, an `errdefer` in deferred code, and assigning the wrong type to a `!T` field.
