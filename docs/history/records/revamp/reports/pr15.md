Slices and bytes: open ranges, writable slices, copy/fill/swap, and reading and writing fixed-width numbers in byte buffers. These are the byte-level foundations Rig's standard library and a page-based store need.

## Language

- **Open ranges:** `xs[a..]`, `xs[..b]`, and `xs[..]`, on String, arrays, Vec, and slices. An open side anywhere else (`for i in 0..`) gets one diagnostic.
- **Writable slices:** `![]T` and `!xs[a..b]`. A writable slice is a write borrow of its root:
  - it cannot be copied, and reslicing reborrows it;
  - it can be returned only from a `!` parameter;
  - `s[i] = v` and `for x in !s` work;
  - where a `[]T` is expected, it is lent as a read.
- **`!dst.copy(src)`, `!s.fill(v)`, and `!s.swap(i, j)`** work on slices, arrays, and Vec. Every length and index check panics in every build mode.
- **Fixed-width numbers in bytes:** `buf.read[U32, .little](at)` and `!buf.write[U16, .big](at, v)` read and write any integer or float, with a built-in `Endian` enum and bounds checks in every build mode. A generic `T` is allowed.
- **Arrays where a slice is expected:**
  - A temporary (`!b.copy([9])`) is passed directly.
  - A named array is passed as `?a` (for `?a[..]`) or `!a` (for `!a[..]`), so the borrow stays visible.
  - A bare named array is rejected with a hint.

## Review

An independent review ran about 2,250 probes and fuzz programs. It found no memory corruption, and every bounds check fired in Debug and `--release=fast`. It found:

- **A soundness break, now fixed:** `fill` and `copy` could duplicate an exclusive write borrow. Elements that hold a borrow are now rejected, as `[n of x]` already rejects them.
- **Wrong rejects, now fixed:**
  - copying a local into a caller's buffer;
  - a source staying borrowed after `copy`;
  - one writable slice passed twice as a read;
  - an open range before a line break.
- **Six doubled or misleading diagnostics, now corrected.**

The implementer's own adversarial pass also closed a hole: `!` of a read-only slice is rejected.
