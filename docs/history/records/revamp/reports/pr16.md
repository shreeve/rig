Closures can now be passed to functions. A `?fun(A) -> R` / `?sub(A)` parameter is a *borrowed callable*: the callee may call it and pass it on, but never store it, so it cannot outlive what it captured.

## Language

- **Borrowed callables:** `fun sort[T](xs: ![]T, less: ?fun(?T, ?T) -> Bool)` is called as `sort(!v, |a, b| a < b)`. A function name (`sort(!v, desc)`), `?f` of a named closure, and `?cb` of an owned closure are accepted too.
- **Borrow captures:** `|?x|` and `|!x|` borrow for as long as the closure lives, so `each(?v, |!total, n| total += n)` adds into a local.
- **Inline assignment:** a closure's inline body may be an assignment, as in `|!total, n| total += n`.
- **Generic inference through closures:** `map(?names, |s| s.len)` infers the result type from the literal.
- **Where `?fun` may appear:** only as a parameter, local, or result type. It is rejected in fields, collections, `Cell`, and module bindings.
- **Liveness:** a closure binding keeps its borrows until its last use, not until the end of its scope.
- **Lowering:** a 16-byte fat pointer (`rig.FnRef`) with one indirect call and no allocation.
- New `examples/sort.rig`.

## Soundness

An independent review found two use-after-free holes, and both are closed by general rules:
- **Callable results.** Calling *any* callable (a named closure, a borrowed one, a parameter, or a call's result) gives a result that carries the callable's borrows.
- **Closure parameters.** A borrow a closure receives as a parameter lasts one call. Storing it through a capture, which outlives every call, is rejected.

The lead probed both rules through forwarding parameters, rebinding inside a callee, nested closures, whole-value stores, and generic callees. Every escape was rejected and legitimate uses still run.

Also fixed from the review:
- `|!x|` of a binding that is never otherwise written;
- `|?f|` of a named closure;
- a regression that treated a generic `?T` of function type as a borrowed callable;
- a regression that rejected `!g` of a function-pointer local;
- diagnostics that gave several errors or broken hints for one mistake.

## Known and deferred (predates this branch; a separate change)

A read borrow of plain data is a copy in the emitted Zig, and a read-borrow local is a pointer. So a local rebound to a function's `?T` result fails in Zig; this is recorded as a known test. The same rule passes `?[1000000]Int` by value, which costs an 8 MB copy and makes the frame check undercount. That representation fix is next.
