Four syntax cleanups, each with a full migration of tests, examples, and docs, and a hint that points the old spelling at the new one.

## Language

- **The fill literal is `[n of x]`**, count first, matching the type `[n]T`: `[4096 of 0]`, `[n of 0]`, `grid: [2][3]Int = [2 of [3 of 0]]`.
  - `of` is a keyword only directly inside brackets after a value; everywhere else it is an ordinary name.
  - `[x; n]` and the `;` token are gone. `[0; 4]` hints `[4 of 0]`, and `[U8; 4]` hints `[4]U8`.
- **`*Node?` is an optional handle:** handle sigils bind tighter than type suffixes, so `next: *Node?` needs no parentheses. A handle to an optional is `*(Node?)`. Borrows still cover the whole type: `?T?` is a borrow of an optional.
- **`<self`** is the short form of a consuming receiver, alongside `?self` and `!self`. `self: Self` stays valid.
- **Single-field variants take their payload by position:** `.some(7)`, `Option.some(7)`, `.circle(2)`. Multi-field variants and struct constructors still set fields by name.

## Also

- **A handle to a borrow (`*(?Int)`) is now rejected.** A handle holds a value, never a borrow. `main` accepted this.
- **Every type printed in a diagnostic parses back to the same type.** A new round-trip test covers 33 tricky spellings, and fixes `N??` → `(N?)?`.
- In an expression type argument, `*X?` means what it means in a type. The parser layer marks parenthesized handles by span, so the checker never reads source text.

## Review

An independent review found no critical or high findings. Its medium finding (chained handles in type arguments) and its eight low ones (hints and printing) are fixed with tests, and fuzzing found no crash or hang.
