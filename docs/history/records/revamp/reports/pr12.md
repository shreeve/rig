Structural equality for structs, enums, arrays, and slices, plus ordering for strings and byte slices: two foundations the Rig-written standard library needs (`HashMap`, `sort`).

## Language

- **`==` and `!=` are structural** over *equatable* types:
  - numbers, `Bool`, `String`, errors;
  - plain enums, and payload enums whose payloads are equatable;
  - optionals, arrays, and `[]T` slices of equatable types;
  - structs with no `drop` whose fields are all equatable, including generic instances and imported structs.
- **Rejected, with the offending field path named:** handles (`*T`, `~T`: identity versus content would be ambiguous), `Vec`, `Cell`, `Signal`, functions and closures, views, and types with `drop`. No `eq` method is ever called implicitly.
- **Floats compare IEEE-style everywhere,** including inside structs and slices, so NaN never equals itself.
- **Variant literals:**
  - A bare variant (`s == .empty`) compares the tag only. This works on any enum and puts no requirement on `T`.
  - A payload literal (`s == .circle(r: 1.0)`) takes its type from the other operand, and requires the enum to be equatable.
- **Ordering:** `<`, `<=`, `>` and `>=` compare `String` and `[]U8` byte by byte, with a prefix first. Generic `.ordered` admits `String`, so `max("a", "b")` works.
- **Generic bodies:** `==` on a type holding `T` is checked for each instance.
- **Docs:** SYNTAX now says "*prefix* `!` is never not" (`!=` is the not-equal operator).

## Review

An independent review found two critical bugs and one high one in the variant-literal path (a missing equatability check). They are fixed, along with NaN in same-slice comparisons, array-literal operands, `T?` vs `T` in generic bodies, `Void == Void`, and qualified names in reasons. All of its repros run correctly and leak-free, or give one diagnostic.

Not done here: reading array *constants* inside other constants. That limitation exists on main and needs its own change.
