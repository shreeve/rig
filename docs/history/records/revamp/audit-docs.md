Scope: README.md, FAQ.md, SPEC.md, SYNTAX.md, AGENTS.md, docs/{DESIGN,INTERNALS,ROADMAP,zig-0.16}.md,

Method:
- `./test/run -v doc`: 272 passed, 0 failed (SPEC 162, SYNTAX 98, README 6, DESIGN 2, INTERNALS 2,
  FAQ 1, test-README 1). Every checked ```rig block is truthful, so the defects are all in prose,

  found 0 broken links or anchors in the 12 files.

- I compared the IR and schema excerpts with rig.grammar @schema and `rig normalize`.
- I compared the SPEC and SYNTAX examples. 19 of SYNTAX's 101 rig blocks are identical to SPEC blocks,
  and 17 more are more than 80% similar.

Overall:
- SPEC is accurate almost everywhere, and every doc example passes.
- The errors are prose left behind by the recent syntax batches:
  - paren-free calls are still taught in SYNTAX
  - "no private fields" appears in SYNTAX and ROADMAP
  - two SPEC sentences are false about closures
  - Box is missing from every "owning values" and "what allocates" list
  - the contributor docs (INTERNALS, SYNTAX appendices) describe the IR, the read-borrow
    representation, and the grammar as they were before the batches
- No finding is memory-unsafe, so none is critical.
- The structural problem is duplication. The same rules are restated across SPEC, SYNTAX, DESIGN,
  INTERNALS, FAQ, and README, and the unchecked restatements are exactly where the drift is.

## LANGUAGE QUESTIONS

- **Q1 (from D8).** Should a function keep being barred from returning a slice of a `?[N]T` parameter (`fun head(xs: ?[3]Int) -> []Int` with `?xs[0..2]`)?
  - The restriction's reason ("the function's own copy") stopped being true when read borrows of arrays became `*const [N]T`, so the slice would now point into the caller's array.
  - Lifting it accepts more programs (a language change), and it must also hold inside generic bodies, where `ReadBorrow(T)` decides the representation.
  - If the rule stays, only the SPEC wording and the diagnostic text change.
- No other disagreement needs a language decision. In every other case the docs should describe the compiler.
