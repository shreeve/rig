## LANGUAGE QUESTIONS

- Q1. Is `Int(E.a)`, a plain enum variant's value named through its type, a compile-time constant? SPEC says such a conversion "must fit the target at compile time", yet `K = Int(E.a)` is rejected as a module constant and as an array length ([ei.rig]).
- Q2. Should declaring a type, alias, or function named like a built-in type (`struct Int`, `struct I16`) be rejected? Today it is accepted and unreachable (L2). Rejecting it narrows what Rig accepts.
- Q3. Should an untyped wrapping expression (`3 +% 4`) be a constant where no type is in context (an enum value)? Today it is "not constant".
- Q4. `Vec[T]` of an owning struct, and arrays of owners, need `Box`/`*T`; the runtime (`Vec`, `dropElement`) could drop them directly. Is this a permanent rule or a v1 restriction?
- Q5. Several shadowing and "unread local" errors exist because Zig forbids them. The emitter could rename or discard instead. Are they Rig rules or backend artifacts?

## Weak tests

- `test/behavior/types/number_limits_alias.rig` uses `LAST = Byte.max` only in `print`, never as an array length or compile-time argument, so M1 slips through.
- There is no test that sizes `Cell[[N]T]` (C1), and none for `==` on an imported struct that holds the declaring module's generic instance (H1).
- There is no test of enum values from module constants, from imported constants (public and private), or from conversions (H2).
- There is no test of by-value type chains deeper than a few links (M3).

## Biggest simplification

Constant evaluation is spread over two name providers (`CheckedNames`, `ConstNames`), three passes (resolve, typecheck, emit), and checker facts that only exist after typecheck (`typeOf` for literal types, `symbolOf` for conditions, resolved aliases). That spread is behind H2, M1, D4, and L11. One `ConstEnv` (scope, `before`, the type params, and the expected `IntInfo`), read only through declarations and `const_ints` and never through checker facts, would let `foldModuleConsts`, `checkEnumValues`, `resolveCtInt`, typecheck, and emit fold identically; enum values could then be emitted from their folded `Field.value`. The second-largest win is to make every cross-module read carry its store explicitly: one `memberOf` returning local-store types, and a Debug assert in `TypeStore.get`. That removes the membersOf/nominalDecl split (M2, L10) and the id-confusion class behind H1. With the leaf/node fact maps (D2) and the duplicated worklists (D3), roughly 200 lines go and several drift bugs become impossible.
